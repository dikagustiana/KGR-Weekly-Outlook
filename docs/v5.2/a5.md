## Cara menjalankan

```bash
pnpm install
npx playwright install --with-deps chromium        # lokal: sudah ada lewat PLAYWRIGHT_BROWSERS_PATH
sudo apt-get install postgresql-16 faketime        # + binari PostgREST 12.2.3 di PATH
pnpm e2e                                           # ±6 menit; hasil di tests/e2e/out (diabaikan git)
E2E_ONLY="T7 F19" pnpm e2e                         # sebagian; E2E_BUILD=never memakai apps/web/.next dari `pnpm e2e:build`
```

Semua path, port, URL, kunci dan user datang dari env (`tests/e2e/stack/env.sh`). `E2E_SKIP_UP=1` menjalankan journey yang sama terhadap tumpukan lain (PRD B, T19:
`E2E_BASE_URL`, `E2E_SUPA_URL`, `E2E_ENV_LABEL`, `E2E_EMAIL_DOMAIN` atau `E2E_EMAIL_<ROLE>`, `E2E_PASSWORD`, `E2E_CLOCK=real`; tanpa `E2E_PG_URL` langkah SETUP berhenti dan tidak menulis ke database yang
bukan miliknya).

| Berkas | Isi |
|---|---|
| `stack/up.sh`, `down.sh`, `build.sh` | cluster PG16 sendiri (port 54329, di bawah faketime) → shim → migrasi dua kali → seed → `sql/users.sql` → PostgREST 12 (anon, `db-max-rows=1000`) → mock → `next build` + `next start` |

## Temuan A5 (Q-v5.2-50 … 54) — butuh keputusan pemilik; kodenya tidak diubah di irisan ini

- **Q-v5.2-51 — rebuild lewat route cron berjalan tanpa sesi dan menulis data yang berbeda (R45/R46, F19).** `GET /api/cron/rebuild` memakai klien servis untuk antrean, tetapi builder kas
  membaca minggu lewat `computeForWeek`, yang memakai klien sesi (`supabaseServer()`); di route cron itu klien anon, RLS membuat minggu terbaca kosong. Akibatnya (F19, XFAIL): rebuild satu tanggal lewat cron
  tidak menulis `solvency_monthly` maupun `ccc_daily`, dan mengganti baris forecast `pl_daily_v4` pada tanggal data dari basis `po` menjadi `runrate` (hash `pl_daily_v4` Agustus sesudah rebuild sesi Finance
  ≠ sesudah rebuild cron; baris `po` tanggal 27/08 untuk Revenue/COGS LB main dan Trading dan COGS Blasting diganti baris `runrate`, 301 → 299 baris). Dua rebuild cron berturut-turut identik satu sama lain (ke-1 = ke-2 lulus); yang berbeda adalah cron vs sesi. Artinya cron harian 05.00 WIB di production
  menurunkan mart yang dibangun sesi. Usul: builder menerima klien yang sama dengan antrean (atau `computeForWeek` memakai klien servis di konteks cron). Sampai ada R untuk ini, empat cek F19 tetap XFAIL
  dan tidak menggagalkan job; ketika diperbaiki mereka menjadi XPASS dan penandanya dihapus.
  **Status: ditutup oleh irisan A1d** (`docs/v5.2/a1d.md`, cabang `v5.2/a1d-cron-client`): builder dan cron memakai klien dari pemanggil; empat cek F19 menjadi cek biasa.
- **Q-v5.2-50 — C42 tidak bisa lulus lewat layar.** C42 membaca semua baris yield kelas rencana (STD), termasuk yang sudah digantikan tanggal berlaku lebih baru; baris placeholder pola `boneless`

  **Status: ditutup oleh irisan A6** (`docs/v5.2/a6.md`): C42 menilai baris yield efektif dari pola yang dipakai rencana (karkas); baris `boneless` placeholder tidak lagi menahan,
