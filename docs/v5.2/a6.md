## 2. Per requirement

### R75 — urutan tile `(y, x)`

- `apps/web/components/v4/TilePage.tsx:89` mengurutkan salinan `tiles` menurut `(pos.y, pos.x)` sebelum render. Semua layar tile memakai `TilePage` (Minggu ini, Komersial, Rencana v4 dan v5, Input, Outlook bulan, Kas), jadi satu tempat.
  Sebabnya: model Minggu ini menaruh tile v5 (laba rugi, simulasi, keputusan) paling akhir di array; di ≤ 899 px grid satu kolom (`v4.css`: `grid-row: auto !important`) dan urutan halaman = urutan DOM, sehingga laba rugi dan keputusan jatuh di bawah semua tile v4.
- Posisi y tile v5 sudah sesuai §6.1 (`pl-tiles.ts`: laba rugi y 4, tinggi 4 = baris 5–8; `management.ts`: simulasi dan keputusan y 8 = baris 9, tinggi 5 sesuai Q-v5-50; kartu y 2). Tes memastikannya.
- Tes: `apps/web/lib/v5/management-screens.test.tsx`, blok "R75: urutan tile (y, x)…" — model mencantumkan laba rugi sesudah `catatan` (tanpa sortir akan di akhir), render mengurut `(y, x)`, y sesuai §6.1. Lingkungan: vitest.
- `apps/web/app/v4.css` (≤ 899 px): `.v4-user` membungkus (`flex-wrap`, `white-space: normal`). Ditemukan lewat tangkapan layar A6: untuk role selain Manajemen baris akun (e-mail, role, Akun, Keluar) tidak membungkus dan melebarkan halaman Input, Komersial dan Rencana menjadi 476–536 px di viewport 390 px.
  e2e A6 langkah 1b memeriksa enam layar utama di 390 px: tanpa gulir horizontal halaman (tabel tetap bergulir di dalam tile).
- e2e A6 langkah 1 (PG16 lokal + PostgREST 12 + mock auth, role management): di 390 dan 899 px posisi atas `t-laba-rugi < sim-lb < keputusan < ch-harian < t-segmen < catatan`; di 1366 px laba rugi di atas simulasi; tanpa gulir horizontal di ketiga lebar.

pnpm install                                   # lokal tanpa cdn.sheetjs.com: override sementara "@kgr/parsers>xlsx": "0.18.5", jangan di-commit
